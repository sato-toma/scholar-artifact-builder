# Documentation

This directory contains the working documentation for scholar-artifact-builder.

## Structure

- `development-units/` contains plans for independently deliverable areas of work.
- `adr/` contains Architecture Decision Records. ADRs record context and trade-offs; they do not replace implementation plans.

## How to Use These Documents

1. Start with `DEVELOPMENT_PLAN.md` for the product vision and broad roadmap.
2. Choose the relevant development unit from `development-units/`.
3. Read the related ADR before making a PoC-level architectural change.
4. Keep unresolved choices in the development-unit document until implementation evidence requires a decision.

The documentation is intentionally written in English so that future AI agents,
contributors, and maintainers can use the same project vocabulary.
